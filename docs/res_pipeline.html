RES — Reverse Engineer a Song

An REA-style agent loop for audio: tools gather evidence → a provider hypothesizes math equations → the synthesizer verifies → the ledger records every try. Nothing is claimed without a measured score behind it.

2026-10-25 update: the engine now also ships the note layer (beat pairs, 12-TET snap, 808 note events), band-envelope noise layers + the residual chase, loudness parity, seam repair, the fidelity benchmark (original = 100%), and the exact mode (equations + FLAC residual = 99.97%). The current pipeline diagram lives in README.md → System Pipeline Architecture; this page remains a faithful description of the loop's five stages.

05 What makes it trustworthy

measured, never assumed

Every claim in the ledger sits next to corr / SNR / LSD computed against the original audio. The file's untouched remainder is never compared — extra silence would fabricate a collapse.

strict-improvement acceptance

Each candidate edit (reprojection, decay sweep, frequency shift, drop) is accepted only when the section residual strictly decreases — section corr can never get worse.

rollback, not hope

An iteration that fails verification is rolled back from a snapshot. The best state is tracked separately; bad hypotheses cost nothing but a ledger entry.

support masks

Partials are windowed exactly like the SMS engine: attack reaches back one analysis window, hold follows the fitted decay, release fades 0.25 s. No infinite ringing.

honest equations

amplitude is the fitted coefficient, expansions are stable, edits are typed (refit_amplitude / refit_phase / set_decay / set_frequency_offset / drop) — the provider can't invent a channel it wasn't given.

replayable history

Each checkpoint rewrites res_ledger.json, so an agent (or you) can stop mid-loop and inspect the full hypothesis trail.

06 Run it yourself

# numeric provider — the deterministic loop
python main.py res -i "Metre - Lost.mp3" \
       -o data/output/res_mp3 -d 8 \
       --iterations 4

# with an LLM provider (opencode run)
python main.py res -i "song.mp3" \
       --provider opencode --llm-model provider/model \
       --iterations 6 --target-corr 0.98

# machine-readable summary
